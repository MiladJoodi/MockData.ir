فرض کنید دارید روی یک صفحه فرانت‌اند کار می‌کنید و برای نمایش اطلاعات به یک API نیاز دارید، اما بک‌اند هنوز آماده نیست. در این شرایط لازم نیست توسعه فرانت‌اند را متوقف کنید یا همه‌چیز را با داده‌های هاردکدشده جلو ببرید.

می‌توانید یک API موقت داشته باشید که همان endpointهایی را که فرانت‌اند لازم دارد در اختیار شما قرار دهد. به این شکل، کد فرانت‌اند از همان ابتدا با درخواست‌های واقعی HTTP و پاسخ‌های JSON کار می‌کند.

## فقط endpointهایی را بسازید که لازم دارید

لازم نیست برای یک API موقت، همه قابلیت‌های سیستم را پیاده کنید. فقط endpointهایی را بسازید که صفحه‌ای که روی آن کار می‌کنید به آن‌ها نیاز دارد.

مثلاً برای یک صفحه کاربران ممکن است همین چند endpoint کافی باشد:

```http
GET /users
GET /users/42
POST /users
```

حالا فرانت‌اند می‌تواند لیست کاربران را دریافت کند، اطلاعات یک کاربر را نمایش دهد و حتی کاربر جدید ایجاد کند، بدون اینکه منتظر آماده شدن API اصلی بمانید.

## حالت‌های خطا را هم تست کنید

یکی از مزیت‌های API موقت این است که فقط برای تست حالت عادی استفاده نمی‌شود. می‌توانید عمداً پاسخ‌های مختلف برگردانید و ببینید UI در هر حالت چه رفتاری دارد.

مثلاً اگر کاربری وجود نداشته باشد، API می‌تواند `404` برگرداند. اگر اطلاعات ارسال‌شده مشکل داشته باشند، می‌توانید `422` برگردانید.

```http
GET /users/42 HTTP/1.1
Accept: application/json
```

با این روش، حالت‌هایی مثل «کاربر پیدا نشد»، خطای اعتبارسنجی و پیام‌های خطا را قبل از آماده شدن بک‌اند واقعی هم می‌توانید در فرانت‌اند پیاده و تست کنید.

> API موقت فقط برای تست مسیر موفق نیست. می‌توانید با آن حالت‌های مختلف خطا را هم قبل از آماده شدن بک‌اند واقعی بررسی کنید.

## ساختار پاسخ را شبیه API واقعی نگه دارید

اگر قرار است API واقعی در نهایت اطلاعات کاربر را با فیلدهایی مثل `id`، `name` و `email` برگرداند، API موقت هم بهتر است همین ساختار را داشته باشد.

این موضوع مهم است چون وقتی بک‌اند واقعی آماده شد، قرار نیست فقط به خاطر تفاوت ساختار داده‌ها بخش زیادی از فرانت‌اند را تغییر دهید.

> هرچه ساختار API موقت به API اصلی نزدیک‌تر باشد، جایگزین کردن آن در آینده ساده‌تر خواهد بود.

هدف API موقت این نیست که یک نسخه کامل از بک‌اند بسازید. فقط باید چیزی در اختیار فرانت‌اند قرار دهد که بتواند با آن توسعه و تست شود.

## API موقت چه زمانی مفید است؟

هر وقت بک‌اند هنوز آماده نیست اما فرانت‌اند به API نیاز دارد، یک API موقت می‌تواند زمان انتظار را حذف کند.

می‌توانید با آن UI را توسعه دهید، درخواست‌های API را تست کنید، حالت‌های loading و error را ببینید و حتی برای دمو از آن استفاده کنید.

بعد از آماده شدن API واقعی، endpointهای موقت را با endpointهای اصلی جایگزین می‌کنید.
