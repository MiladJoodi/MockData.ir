فرض کنید دارید روی یک پروژه فرانت‌اند کار می‌کنید، ولی هنوز API آماده نیست. خب طبیعتاً نمی‌توانید منتظر بمانید تا بک‌اند کامل شود و بعد کارتان را شروع کنید.

اینجاست که Mock Data به کار می‌آید.

Mock Data در واقع داده‌ای ساختگی است که برای شبیه کردن شرایط پروژه به دنیای واقعی استفاده می‌شود. مثلاً به جای اینکه منتظر API واقعی بمانید، می‌توانید چند کاربر ساختگی داشته باشید و UI را با همان‌ها بسازید و تست کنید.

## چرا از Mock Data استفاده کنیم؟

یکی از کاربردهای اصلی Mock Data این است که فرانت‌اند و بک‌اند لازم نیست همیشه همزمان آماده باشند.

مثلاً می‌توانید قبل از آماده شدن API، صفحه لیست کاربران را بسازید، حالت‌های مختلف آن را ببینید و مشکلات UI را پیدا کنید.

حتی می‌توانید حالت‌هایی مثل لیست خالی، تعداد زیاد کاربران، اطلاعات ناقص یا خطای API را هم تست کنید.

> Mock Data کمک می‌کند قبل از آماده شدن بک‌اند، توسعه و تست فرانت‌اند را شروع کنید.

برای نمونه:

```json
{
  "id": "user_01",
  "name": "Ada Lovelace",
  "email": "ada@example.com"
}
```

این اطلاعات واقعی نیستند، اما برای توسعه و تست کاملاً قابل استفاده‌اند.

## یک Mock Data خوب چه شکلی است؟

Mock Data قرار نیست فقط چند مقدار تصادفی باشد. بهتر است ساختار آن شبیه چیزی باشد که در پروژه واقعی دریافت می‌کنید.

اسم فیلدها و نوع داده‌ها را ثابت نگه دارید و از مقادیری استفاده کنید که به چیزی که در پروژه می‌بینید نزدیک باشند.

مثلاً اگر API واقعی یک user برمی‌گرداند، Mock Data هم بهتر است همان ساختار را داشته باشد.

> ساختار Mock Data را تا حد ممکن با ساختار API واقعی هماهنگ نگه دارید تا بعداً تغییرات کمتری در فرانت‌اند لازم باشد.

## MockData چه کمکی می‌کند؟

در MockData می‌توانید برای پروژه‌تان داده‌های مختلف تولید کنید، برای تست API یک endpoint موقت داشته باشید و با JSON Workbench هم JSONها را فرمت، اصلاح یا تبدیل کنید.

> هدف ساده است: داده‌ای که برای توسعه و تست لازم دارید داشته باشید و برای شروع کار روی فرانت‌اند منتظر آماده شدن بک‌اند نمانید.
