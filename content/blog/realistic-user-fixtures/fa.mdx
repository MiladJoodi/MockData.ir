وقتی روی یک پروژه فرانت‌اند کار می‌کنید، خیلی وقت‌ها برای ساخت و تست UI به چند User نیاز دارید.

برای شروع می‌توانید چند داده ساده داخل پروژه قرار دهید، اما اگر همه Userها اسم‌هایی مثل `John Doe` و ایمیل‌هایی مثل `test@example.com` داشته باشند، خیلی از مشکلات UI خودشان را نشان نمی‌دهند.

بهتر است داده‌هایی داشته باشید که از نظر ساختار و مقدار، به چیزی که قرار است از API دریافت کنید نزدیک باشند.

## فقط اسم و ایمیل را تغییر ندهید

اگر User در پروژه فقط `name` و `email` دارد، همان فیلدها کافی هستند. اگر اطلاعاتی مثل `role`، `avatar` یا `phone` هم دارید، بهتر است آن‌ها را هم در داده Mock قرار دهید.

مثلاً:

```json
{
  "id": "usr_1001",
  "name": "Samira Nouri",
  "email": "samira.nouri@example.com",
  "role": "developer"
}
```

لازم نیست داده‌ها پیچیده باشند. مهم این است که ساختار و فرمت آن‌ها شبیه چیزی باشد که در پروژه واقعی دریافت می‌کنید.

## از اطلاعات واقعی استفاده نکنید

گاهی برای اینکه سریع‌تر به داده برسید، ممکن است چند User را از دیتابیس اصلی بردارید و داخل پروژه قرار دهید. بهتر است این کار را نکنید.

داده Mock را می‌توانید خودتان تولید کنید و هر تعداد رکورد که لازم دارید بسازید.

> اطلاعات کاربران واقعی را وارد Mock Data نکنید. داده‌های ساختگی را خودتان تولید کنید تا بتوانید آن‌ها را بدون نگرانی داخل Git قرار دهید یا با تیم به اشتراک بگذارید.

## همه Userها را شبیه هم نسازید

اگر همه Userها اسم کوتاه، ایمیل کوتاه و اطلاعات کامل داشته باشند، UI فقط در یک حالت تست می‌شود.

برای تست بهتر، می‌توانید شرایط مختلفی را در داده‌ها قرار دهید:

* اسم‌های کوتاه و طولانی
* ایمیل‌های با طول متفاوت
* نقش‌های مختلف مثل `developer` و `admin`
* بعضی فیلدهای خالی یا `null`

مثلاً:

```json
[
  {
    "id": "usr_1001",
    "name": "Samira Nouri",
    "email": "samira.nouri@example.com",
    "role": "developer"
  },
  {
    "id": "usr_1002",
    "name": "Alexandra Johnson-Williams",
    "email": "alexandra.johnson@example.com",
    "role": "admin"
  }
]
```

این کار می‌تواند مشکلاتی مثل به‌هم‌ریختن جدول، بریده شدن متن یا مشکل در نمایش موبایل را زودتر مشخص کند.

| وضعیت        | نمونه                           |
| ------------ | ------------------------------- |
| نام طولانی   | `Alexandra Johnson-Williams`    |
| ایمیل طولانی | `alexandra.johnson@example.com` |
| فیلد خالی    | `"phone": null`                 |
| نقش متفاوت   | `"role": "admin"`               |

## برای تست، بعضی idها را ثابت نگه دارید

اگر در تست‌ها قرار است همیشه یک User مشخص را پیدا کنید، بهتر است `id` آن ثابت باشد.

مثلاً می‌توانید همیشه User با `id` برابر `usr_1001` را در تست‌ها درخواست کنید.

برای بقیه Userها هم اگر به تنوع بیشتری نیاز دارید، می‌توانید `id`های مختلف تولید کنید.

## وقتی Userهای بیشتری لازم دارید

ساختن چند User به صورت دستی مشکلی ندارد، اما وقتی برای pagination، جستجو یا تست جدول به صدها رکورد نیاز دارید، وارد کردن همه آن‌ها به صورت دستی وقت‌گیر می‌شود.

اینجاست که یک [Mock Data Generator](https://mockdata.ir/generator) می‌تواند کمک کند.

با آن می‌توانید تعداد زیادی User با همان ساختار تولید کنید و هر وقت لازم بود دوباره داده جدید بسازید.
